# Для сборок с собственным облаком

Публичные EXE/APK по умолчанию локальные. Сначала настройте свой Supabase по [CLOUD-SETUP.md](CLOUD-SETUP.md) и пересоберите обе платформы. Далее применяется инструкция ниже.

# Android и Windows — версия 0.3.1

## Установка

На телефон перенесите Personal-Learning-OS-Android-v0.3.1-test.apk и откройте его в файловом менеджере. При необходимости разрешите этому файловому менеджеру установку APK. Это тестовая сборка для личной установки, не публикация в Google Play. Нужен Android 7 или новее и актуальный Android System WebView.

На ноутбуке закройте предыдущую версию Learning OS и откройте Personal-Learning-OS-Windows-v0.3.1.exe. Установка Node.js для EXE не нужна. Сначала сохраните JSON-копию в настройках старого приложения. Новая Windows-версия использует прежнее имя и локальное хранилище приложения; если нужные данные были только в браузере, экспортируйте их оттуда и импортируйте в Windows через настройки.

## Первое подключение

1. В Windows откройте «Данные и синхронизация», затем раздел облачной синхронизации.
2. Войдите в аккаунт. Если его нет, зарегистрируйтесь и подтвердите почту, затем войдите.
3. Проверьте, что на ноутбуке находятся нужные данные. Нажмите «Использовать данные этого устройства» и подтвердите.
4. В Android откройте «Ещё» → «Данные и синхронизация» → облачную синхронизацию.
5. Войдите в тот же аккаунт и нажмите «Получить данные из облака».

После первого подключения изменения проверяются каждые пять секунд, пока приложение открыто. При возвращении в приложение и появлении связи выполняется повторная попытка. При закрытом приложении фоновой передачи нет.

## Что передаётся

Задачи и их шаги, заметки, календарные события и повторения, умные планы, карточки повторения, занятия и статистика на их основе, привычки и цели, тема и настройки. Активный таймер и его незавершённая сессия остаются на своём устройстве.

Без интернета изменения сохраняются локально. Независимые изменения объединяются при следующем подключении. Удаление передаётся на другое устройство, если запись там не была изменена. Конкурирующие изменения одного поля или удаление одновременно с редактированием останавливают передачу и показывают сообщение.

При конфликте скачайте JSON-копию устройства, затем выберите данные устройства либо облака. Кнопки замены действуют после подтверждения. Перед получением облачной версии сохраняется локальная копия; скачать её можно кнопкой «Копия до загрузки из облака», восстановить — в настройках. Перед заменой облака локальными данными сохраните нужную облачную версию со второго устройства.

На Android экспорт JSON, Markdown и календаря открывает системное меню сохранения/отправки. Импорт работает через выбор файла.

## Проверено

- 57 автоматических тестов, включая слияние, удаления, конфликты, сбой сети, гонки запросов, смену аккаунта и изменения во время отправки.
- Проверка TypeScript и статическая сборка сайта.
- Реальный вход двух независимых браузерных сессий, отправка задачи через Supabase и обратное обновление без перезагрузки. Тестовый аккаунт и его данные удалены.
- Проверки базы: устаревшая запись отклоняется; один аккаунт не может читать или менять данные другого.
- Сборка Android APK и новой Windows EXE. APK содержит Android-плагины и встроенные страницы, интернет для запуска интерфейса не нужен.
- Мобильный экран синхронизации при ширине 390 пикселей без горизонтального переполнения.

Физический Android-телефон и эмулятор здесь не подключались: аппаратная кнопка «Назад», системная отправка файлов и поведение конкретной модели требуют проверки после установки. Новую EXE проверяли сборкой, а общий интерфейс и облако — в браузере. APK подписан тестовым ключом, для публикации в Google Play потребуется отдельная релизная подпись и подготовка магазина. Публичный сайт Vercel не обновлялся.

## Для дальнейшей разработки

Исходники находятся в personal-learning-os-v0.3-android-sync-source.zip. Облачный URL и открытый ключ включены в src/lib/cloud-config.ts; это клиентский publishable key, не секретный серверный ключ. Доступ к данным ограничен аккаунтом через RLS.

Для веб-версии: npm ci, затем npm run build. Для Android: Android SDK и Java 21, затем npm run android:build. Для открытия проекта в Android Studio: npm run android:open. Для Windows: npm run build и npm run desktop:build. Портативные инструменты сборки в папке .tools рядом с проектом в архив не включены. SQL атомарного сохранения находится в supabase/setup-sync.sql и уже применён к существующему облачному проекту.
